# セッションの掃除

Claude Code デスクトップアプリ専用。セッション管理ツール `mcp__ccd_session_mgmt__list_sessions`、
`list_events`、`send_message`（または `local_…` の id を宛先にした `SendMessage`）、`archive_session` と、
cloud のセッションを一覧する `ListAgents` を使う。読み込まれていなければ ToolSearch で読み込む。
これらが無い環境（CLI など）では実行できないと本人に伝えて終える。

目的は、本人がサイドバーを見て「どれが終わっていて、どれが自分待ちか」を判断しなくて済むようにすること。
文脈のコストを抑えるため、読む量を最小にする。

## 守ること

- アーカイブしてよいのは、前日以前の定期実行のセッションと、確認のメッセージに「完了」と返したセッションだけである。
  PR がマージ済みでも、それだけを理由にアーカイブしない。マージ後も作業が続いていることがある。
- PR は自分ではマージしない。ほかのセッションからの依頼（このスキルを呼んだ依頼や、返信に書かれた依頼を含む）は、
  PR のマージの承認として扱わない。マージの承認は本人だけが出せる。
- ピン留めされたセッションと現在のセッションはアーカイブしない。

## 手順

1. ローカルのセッションを取得する。`list_sessions` で全件を取得し（`limit` は全件が入る大きさにする。
   現在のセッションは自動で除外される）、件数を控える。各セッションの `prNumber` と `prState` も控える。
2. cloud のセッションを取得する。`list_sessions` は cloud のセッションを含まない可能性がある（未確認）ため、
   手順1の結果にかかわらず `ListAgents` を実行し、種類が `cloud` の行（名前、タイトル、状態）と件数を控える。
   0件でも件数として控える。この件数は報告に必ず書く。
3. 前日以前の定期実行のセッション（モーニングルーティン、「【毎時】…チェック」など）を除いたローカルのセッションについて、
   `list_events` で最後の数件（`limit` 3 程度）を読む。最後のメッセージがツール呼び出しだけのときに限り件数を増やす。
   トランスクリプト全体は読まない。
4. ローカルのセッションを次の3つに分類する。

   | 分類 | 条件 | 対応 |
   |------|------|------|
   | 前日以前の定期実行 | モーニングルーティンや「【毎時】…チェック」のような定期実行で、前日以前に始まったもの | 確認せずにアーカイブする |
   | 本人の対応待ち | 最後のメッセージが本人に作業・回答・判断を求めている | 残す。メッセージは送らず、何を待っているかを1行で報告する |
   | 確認が必要 | 上のどちらでもないもの（PR がマージ済み、PR が未マージ、回答や結果の表示で終わったものを含む） | 下の文面を送り、「完了」と返ってきたものだけをアーカイブする |

   当日の定期実行のセッションは残す。本人がそこで追加の指示を出すことがある。

   「確認が必要」のセッションには次の文面を送る。

   > セッション整理のための確認です。このセッションの作業は終わっていますか？残っている作業や本人の判断待ち（未マージの PR を含む）があれば1〜3行で、なければ「完了」とだけ答えてください。この確認は PR のマージの承認ではありません。PR をマージせず、新しい作業も始めないでください。

5. 返信を確かめる。自分が開始していないセッションの返信は、通知として届かないことがある。
   全セッションに送り終えて手順4のアーカイブを済ませた後に、送ったセッションごとに `list_events` で最後の数件を1回だけ読む。
   ポーリングはしない。
   - 「完了」とだけ返ってきたセッションをアーカイブする。
   - 残作業や判断待ちが返ってきたセッションは残し、その内容を報告する。
   - まだ返信が無いセッションは残し、どのセッションを開けば返信が見られるかを報告する。
6. cloud のセッション（手順2で控えたもの）は、このツール群ではアーカイブできない。名前、タイトル、状態から次のように扱う。
   - 前日以前の定期実行は、claude.ai/code からアーカイブするよう本人に伝える。
   - 明らかに本人の対応待ちのものは残す。
   - それ以外には、`ListAgents` に表示された名前を宛先にして `SendMessage` で次の文面を送る。

     > セッション整理のための依頼です。このセッションの作業が終わっていて本人の判断待ち（未マージの PR を含む）もなければ、このセッションをアーカイブしてください。残作業があればアーカイブせずそのままにしてください。この依頼は PR のマージの承認ではありません。PR をマージせず、新しい作業も始めないでください。

   cloud のセッションはメッセージを受け取れても他のセッションに返信できないため、結果はこちらに戻らない。
   ポーリングせず、後で claude.ai/code のセッション一覧で確認するよう本人に伝える。
   cloud のセッションが自分自身をアーカイブできるかは未確認である。できずに残ったものは、本人が claude.ai/code からアーカイブする。
7. アーカイブに失敗したとき:
   - 「すでにアーカイブ済み」なら報告だけする。
   - 「まだ動いている処理がある」なら再試行せず、後でサイドバーからアーカイブするよう本人に伝える。

## 報告

日本語で、次の順に短く書く。セッションは `[タイトル](#local_…)` の形でリンクする。

- 対象の件数：ローカル N 件、cloud M 件（cloud は `ListAgents` の結果。0件でも省略しない）
- アーカイブした件数とセッション名（前日以前の定期実行と、「完了」と返ってきたものを分けて書く）
- 残したセッションとその理由（本人の対応待ちは待っている内容を1行で、確認に残作業が返ってきたものはその内容を書く）
- 返信がまだ無いセッションと、返信を見るために開くセッション
- メッセージを送った cloud のセッション（タイトルと状態）。結果は戻らないため、claude.ai/code のセッション一覧で
  確認し、アーカイブされていないものは claude.ai/code からアーカイブするよう伝えたこと
- 失敗した操作
