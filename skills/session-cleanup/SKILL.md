# セッションの掃除

Claude Code デスクトップアプリ専用。セッション管理ツール `mcp__ccd_session_mgmt__list_sessions`、
`list_events`、`send_message`（または `local_…` の id を宛先にした `SendMessage`）、`archive_session` を使う。
読み込まれていなければ ToolSearch で読み込む。これらが無い環境（CLI など）では実行できないと本人に伝えて終える。

目的は、本人がサイドバーを見て「どれが終わっていて、どれが自分待ちか」を判断しなくて済むようにすること。
文脈のコストを抑えるため、読む量と送るメッセージを最小にする。

## 手順

1. `list_sessions` で全セッションを取得する。`limit` は全件が入る大きさにする（現在のセッションは自動で除外される）。
   各セッションの `prNumber` と `prState` を使う。
   `list_sessions` に出ない cloud のセッションを拾うため、`ListAgents` も実行し、種類が `cloud` の行
   （名前、タイトル、状態）を控える。`list_sessions` が cloud のセッションを含まない可能性がある（未確認）。
2. PR がマージ済みでないセッションだけ、`list_events` で最後の数件（`limit` 3 程度）を読む。最後のメッセージが
   ツール呼び出しだけのときに限り件数を増やす。トランスクリプト全体は読まない。
3. 各セッションを次の4つに分類する。

| 分類 | 条件 | 対応 |
|------|------|------|
| 明らかに完了 | PR が MERGED。または前日以前の定期実行（モーニングルーティンなど） | 確認せずにアーカイブする |
| PR が未マージ | PR が OPEN または Draft | 自分ではマージしない。そのセッションにメッセージを送り、作業が終わったかを判断し、そのリポジトリのルールに従って PR を扱い、短く返信するよう頼む。判断はセッションに任せる |
| 本人の対応待ち | 最後のメッセージが本人に作業・回答・判断を求めている | 残す。何を待っているかを1行で報告する |
| 判断できない | 回答や結果の表示で終わり、明示的な残作業が無い | 候補として一覧し、メッセージを送る前に本人に確認する |

- 同じ PR 番号を複数のセッションが持つことがある（フォーク）。それでも `prState` が MERGED ならアーカイブしてよい。
- 当日の定期実行のセッションは残す。本人がそこで追加の指示を出すことがある。
- 「判断できない」セッションに本人の承認を得たら、次の文面を送る。

  > セッション整理のための確認です。このセッションの作業は終わっていますか？残っている作業や本人の判断待ちがあれば1〜3行で、なければ「完了」とだけ答えてください。新しい作業は始めないでください。

  「完了」と返ってきても、アーカイブする前にもう一度本人に確認する。
4. 状態がはっきりしているセッションにはメッセージを送らない。メッセージを受けたセッションは文脈全体を読み直すため、
   長いセッションほどコストが大きい。
5. アーカイブに失敗したとき:
   - 「すでにアーカイブ済み」なら報告だけする。
   - 「まだ動いている処理がある」なら再試行せず、後でサイドバーからアーカイブするよう本人に伝える。
   - ピン留めされたセッションと現在のセッションはアーカイブしない。
6. 自分が開始していないセッションの返信は、そのセッションがセッション間メッセージを送らない限り通知として届かない。
   ポーリングせず、返信はどのセッションを開けば見られるかを本人に伝える。
7. cloud のセッションは、このツール群ではアーカイブできない。上の分類と同じ基準で扱い、
   明らかに本人の対応待ちのものは残す。「判断できない」ものは、メッセージを送る前に本人に確認する。
   送ってよいセッションには、`ListAgents` に表示された名前を宛先にして `SendMessage` で次の文面を送る。

   > セッション整理のための依頼です。このセッションの作業が終わっていて本人の判断待ちもなければ、このセッションをアーカイブしてください。残作業があればアーカイブせずそのままにしてください。新しい作業は始めないでください。

   - cloud のセッションはメッセージを受け取れても他のセッションに返信できないため、結果はこちらに戻らない。
     ポーリングせず、後で claude.ai/code のセッション一覧で確認するよう本人に伝える。
   - cloud のセッションが自分自身をアーカイブできるかは未確認である。できずに残ったものは、
     本人が claude.ai/code からアーカイブする。

## 報告

日本語で、次の順に短く書く。セッションは `[タイトル](#local_…)` の形でリンクする。

- アーカイブした件数とセッション名
- 残したセッションとその理由（本人の対応待ちは待っている内容を1行で）
- メッセージを送ったセッションと、返ってきた返信
- メッセージを送った cloud のセッション（タイトルと状態）。結果は戻らないため、claude.ai/code のセッション一覧で
  確認し、アーカイブされていないものは claude.ai/code からアーカイブするよう伝えたこと
- 失敗した操作

PR がマージ済みのセッションが多かった場合は、PR のマージで自動アーカイブするアプリの設定
`auto_archive_on_pr_close` があることを1回だけ伝えてよい。
