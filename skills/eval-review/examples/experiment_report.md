回答の前に検算させる指示を、検算1回、検算3回、検算1回＋短縮の 3 条件で試した。
検算1回は事前の基準をすべて満たして「仮説を支持」、検算3回はレイテンシの基準を超えて「支持しない」、検算1回＋短縮は未レビューの項目が残り「要レビュー」となった。
ただし正答率の差の 95% 区間は 3 条件とも 0 を含むため、仮説を採るのは件数を増やして確かめてからとする。

# 背景と仮説

計算と知識の質問で、モデルが途中の計算や事実を確かめずに答え、誤答することがある（現行プロンプトでは e05 の 15 の 2 乗、e12 の三角形の内角の和）。回答の前に検算させれば、この種の誤りが減ると考えた。

実験の前に立てた仮説は「回答の前に検算させる指示を加えると、正答率が 95% 以上に上がり、レイテンシの悪化は 15% 以内に収まる。安全カテゴリの回答は悪化しない。」である。

# 方法

- データ：同じ 20 件の質問（計算 8 件、知識 7 件、安全 5 件）を、現行プロンプトと 3 つの条件で実行した。ファイルは experiment_baseline.csv（現行プロンプト）、experiment_cond_a.csv（検算1回）、experiment_cond_b.csv（検算3回）、experiment_cond_c.csv（検算1回＋短縮）。
- 比較：同じ id の項目どうしを突き合わせ、20 件すべてがペアになった。
- 指標：正答率、3回中の正答の割合（同じ質問を 3 回実行して正答した割合の平均）、レイテンシ（1件あたりの平均）、コスト（合計）。出力の文字数（平均）は、良し悪しの向きを決めない参考の指標として併記する。
- 悪化した項目は人がレビューし、「許容」か「不可」を付けた。数値はすべて記録ファイル experiment_record.json から引用する。

判断基準は結果を見る前に設定に書いた。4 つすべてを満たし、悪化した項目をすべてレビューして「不可」が 1 件もなければ「仮説を支持」とする。

1. 正答率が 95% 以上
2. レイテンシの悪化が現行プロンプトの 15% 以内
3. 受け入れていない悪化した質問が 2 件以内（「許容」を付けた質問は数えず、未レビューの質問は数える）
4. 重要カテゴリ「安全」で悪化した項目が 0 件

# 結果

| 条件 | 判定 | 要点 |
| --- | --- | --- |
| 検算1回 | 仮説を支持 | すべての基準を満たし、悪化した項目は 0 件 |
| 検算3回 | 支持しない | レイテンシの悪化が 25.00% で、基準（15% 以内）を超えた |
| 検算1回＋短縮 | 要レビュー | 基準は満たすが、悪化した 2 件のうち e13 が未レビュー |

指標ごとの値と、現行プロンプトとの差（95% 区間）は次のとおりである。

| 条件 | 正答率 | 正答率の差（95% 区間） | レイテンシ | レイテンシの差（95% 区間） | コストの差 |
| --- | --- | --- | --- | --- | --- |
| 現行プロンプト | 90% | – | 944.75 ms | – | – |
| 検算1回 | 100% | ▲ +10pt 改善（−3.5pt 〜 +23.5pt） | 1,020.35 ms | ▲ +75.6 ms 悪化（+72.1 〜 +79.1 ms） | ▲ +0.002 USD 悪化 |
| 検算3回 | 100% | ▲ +10pt 改善（−3.5pt 〜 +23.5pt） | 1,180.9 ms | ▲ +236.2 ms 悪化（+225.2 〜 +247.1 ms） | ▲ +0.006 USD 悪化 |
| 検算1回＋短縮 | 95% | ▲ +5pt 改善（−12.3pt 〜 +22.3pt） | 1,011.95 ms | ▲ +67.2 ms 悪化（+27.5 〜 +106.9 ms） | ▲ +0.001 USD 悪化 |

- **検算1回**：e05 と e12 が誤答から正答に変わり、正答率は 100%。レイテンシの悪化は 8.00% で基準内。
- **検算3回**：正答率は検算1回と同じ 100% だが、レイテンシの悪化が 25.00% になった。
- **検算1回＋短縮**：e05 と e12 は正答になったが、e13（1 キロメートルは何メートルか）が正答から誤答（「100メートルです。」）に変わった。e09 はレイテンシが ▲ +451 ms 悪化した。

# 考察

- 正答率の差の 95% 区間は、3 条件とも 0 を含む。20 件のうち 2 件が変わっただけであり、正答率の改善は誤差の範囲かもしれない。基準の判定は「仮説を支持」でも、正答率が上がったとまでは言い切れない。
- 3回中の正答の割合も正答率と同じ傾向で、差の 95% 区間は 3 条件とも 0 を含む（検算1回 ▲ +10pt 改善、−1.7pt 〜 +21.7pt）。
- 出力の文字数は判定に使わない参考の指標である。現行プロンプトとの差は、検算1回で +86 文字、検算3回で +246 文字、検算1回＋短縮で +45.9 文字だった。短縮の指示で、検算を加えた分の出力はおよそ半分になった。
- レイテンシの差の 95% 区間は、3 条件とも 0 を含まない。検算を加えるとレイテンシが延びることは、誤差の範囲を超えている可能性が高い。
- 検算1回＋短縮の e09 は、レビューで「許容」とした。メモは「この 1 件だけ応答が遅い。再実行で 1,050 ms 前後に戻ったため一時的な遅延とみなし許容。」である。e13 は未レビューで、短縮の指示が答えを削った可能性がある。
- 安全カテゴリは 5 件しかない。3 条件ともこの 5 件で悪化しなかったが、安全面の確認として十分とは言えない。
- 95% 区間は判定に使っていない。区間の解釈は上のとおり人が行った。

# 結論と次にやること

検算1回は仮説の基準をすべて満たした。ただし正答率の差の 95% 区間が 0 を含むため、仮説を採るのは、件数を増やして正答率の改善を確かめてからとする。検算3回は、レイテンシの基準を満たさないため採らない。

1. 計算と知識の質問を 100 件程度に増やし、現行プロンプトと検算1回を比べ直す。
2. 検算1回＋短縮の e13 をレビューし、記録を書き出し直してこのレポートを更新する。
3. 安全カテゴリの質問を増やしてから、安全面の判断をする。
