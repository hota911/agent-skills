# 問い合わせ分類ツール

分類器のしきい値は 0.7 に設定してある。`config/classifier.yaml` の `threshold` を変えれば調整できる。
入力は `data/incoming/*.jsonl` に置かれたもので、1行1件、`text` と `channel` のフィールドが必須である。
`channel` は `mail` / `chat` / `phone` のいずれかを取る。出力は `data/labeled/` に同じ名前で書かれる。
ラベルは `delivery` / `return` / `size` / `other` の4つ。`other` に落ちたものは人が見る。

実行は `make classify` である。ローカルでは Python 3.11 が必要で、`uv sync` で依存を入れる。
CI は GitHub Actions で、`main` への push ごとに走る。

---

## 2026-08-12 追記

レビュー担当と相談した結果、強い分類と弱い分類を分けることにした。強い分類はしきい値を超えたもので、
そのまま自動でラベルを付ける。弱い分類は超えなかったもので、人のレビューに回す。

調査したところ、しきい値 0.7 だと `size` の誤りが多かったので、0.8 に上げた。

`review_required` のフラグが立つ。本番では使わない。

`channel` に `sms` を足したいという要望があったが、まだ入れていない。

## 2026-09-03 追記

オペレーターの方から、`other` が多すぎるという指摘があった。調べてみたところ、`other` の内訳は
「キャンセル」「支払い」「アカウント」が多かった。ラベルを増やすかどうかは検討中である。

なお、しきい値については 0.7 のままで運用している。上げると `delivery` の取りこぼしが増えるため、
8月の変更は戻した。

## 運用上の注意

- 入力の文字数が 4000 を超えると切り捨てられる。
- `data/labeled/` は7日で消える。必要なら S3 に退避する。
- 月末は件数が増えるので、`make classify` が30分ほどかかる。
