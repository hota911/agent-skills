# PR の説明

GitHub の PR の説明を書くときに読む。
[SKILL.md](../SKILL.md) の規則がそのまま効く場所なので、ここには PR に固有のことだけを書く。

ファイルや行ごとの変更の列挙は書かない。
レビュアーは差分を読めるので、見る箇所を指定するのに要るとき以外は重複になる。
書くのは、変更の前後で振る舞いがどう変わるかである。

書くのは、変更の意図と範囲、なぜ必要か、どこを見てほしいか、確認したこと（実行したコマンドと結果）と確認していないことである。
確認していないことを書くと、レビュアーがどこを疑えばよいかが決まる。
手で動かしていない経路、環境の都合で試せなかった箇所、意図的に範囲外にしたものを挙げる。
PR に固有なのは、説明が差分より長く生きることである。
あとで差分に手を入れたときは、説明もその差分に合わせる。

リポジトリに PR のテンプレートがあるなら、その節を埋め、ここに挙げた中身をその中に入れる。
